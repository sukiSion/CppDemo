0、理念性规则（或者元规则）为具体规则提供理论依据。理想情况下具体规则可以从理念性规则中推导出来
1、在代码中直接表达思想（STL算法）
2、使用ISO标准写c++代码
3、表达意图
4、理想情况下，程序应该是静态类型安全的（编译器可以检测到类型错误）
特别情况：
联合体：在c++17中可以使用std::variant代替
转型：模板的泛型代码减少了转型的需要
C数组：在c++20可以使用std::span可以自动推算出C数组的大小，可以防止范围错误的发生，或者使用Guidelines支持库提供的实现
窄化转换：使用大括号初始化可以检测到窄化转换
5、编译器检查优于运行期检查：可以使用static_assert（c++11）进行编译器检查
6、不能在编译器检查的事项应该在运行期检查：dynamic_cast：沿类指针或者引用沿着继承层次结构进行向上、向下以及侧向的转换。指针转换失败得到一个nullptr，引用转换失败会产生std::bad_cast异常
7、尽早识别运行期错误：例如检查指针和数组的范围，对于转换同样需要检查（应避免转换，对于窄化转换更是）
8、不要泄露任何资源：RAII（构造函数中获取资源，析构函数释放资源）：锁负责互斥量，智能指针负责处理原始内存，STL的容器负责处理底层元素
9、不要浪费时间和空间：使用STL算法简化代码，使用复制构造函数和复制赋值运算符重载会覆盖自动生成的移动构造和移动赋值运算符
10、不可变数据优于可变数据
11、封装杂乱的构建，不要让它在代码中散布开来（STL中的高级构件取代杂乱的代码或者将杂乱的代码封装到一个用户定义的类型和函数中）
12、适当使用辅助工具（静态分析工具、并发工具和测试工具，使用一个以上的c++编译器编译代码）
13、适当使用支持库（C++标准库、Guidelines支持库和Boost库）
