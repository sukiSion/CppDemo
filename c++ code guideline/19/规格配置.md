规格配置是一组确定的、可移植地施行的子集规则（即限制），旨在实现特定的保证
1) 确定：规格配置只做那些可以由编译器实现的局部分析
2) 可移植地施行：不同平台上的不同工具可以给你相同的答案
设定规格配置的原因：
1) 必须处理老式代码又不可能一步到位地应用C++ Core Guidelines的所有规则。
2) 对代码库来说，一些相关的规则可能比其他规则更重要。

# Pro.type 类型安全
类型安全：正确使用类型，因此要避免不安全的转型和联合体
1、避免转型
1) 不要使用reinterpret_cast
2) 不要对算术类型使用static_cast
3) 不要在源类型和目标类型相同的指针类型之间转型
4) 不要在可能有隐式转换的指针类型之间转型
2、不要使用static_cast进行向下转型（应使用dynamic_cast）
3、不要使用const_cast转型去除const
4、不要使用C风格的(T)expression或者函数形式的T(expression)转型
5、在一个变量被初始化之前不要使用它
6、总时初始化成员变量
7、避免裸联合体
8、避免使用va_args

# Pro.bounds 边界安全
边界安全：在所分配的内存范围内的操作
1、不要使用指针算术
2、只使用常量表达式对数组进行索引
3、避免数组到指针的退化
4、不要使用没有边界检查的标准库函数和类型

# Pro.lifetime 生存期安全
生存期安全：只对有效的指针进行解引用
无效的指针情况：该指针没有初始化，或者值为std::nullptr，或者指向数组的范围之外，或者指向被删除的对象。
1、不要对可能无效的指针进行解引用
