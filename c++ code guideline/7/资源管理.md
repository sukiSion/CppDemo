资源管理相关变量：
1) 局部对象：C++运行时作为所有者来自动管理这些资源的生存期。全局对象或者类的成员也是如此、
2) 引用：不是所有者。仅仅借用了不可以为空的资源
3) 原始指针：不是所有者。仅仅借用了可能为空的资源。不可以删除该资源
4) std::unique_ptr：资源的独占所有者。可以显示地释放资源。
5) std::shared_ptr：与其他的shared_ptr共享资源，当是最后一名所有者时会释放资源。可以显式地释放所有权份额
6) std::weak_ptr：不是资源的所有者，但可以通过使用成员函数lock()暂时成为该资源的共享者

# 通用规则
1、使用资源句柄和RAII（资源获取即初始化）自动管理资源（参考raii.cpp）
RAII理念：为资源创建一种代理对象。代理的构造函数获取资源，而代理的析构函数释放资源
RAII中心思想：代理作为局部对象，其所有者是C++运行时，于是它所代理的资源也归C++运行时所有。当作为本地对象的代理对象离开作用域的时候，代理的析构函数也会被自动调用，于时得到了确定性的析构行为
2、原始指针和原始引用不表示所有权
3、优先使用有作用域的对象，不做非必要的堆上分配（注：使用new分配的内存为堆上内存）
有作用域的对象时一个带有自己作用域的对象。它可能是个本地对象、全局对象或者某个类的成员。
注：一个好用的技巧时使用额外的花括号来定义一个人工作用域。由于人工作用域的存在，可以显式地控制一个本地对象的生存期

# 内存分配和释放
C++new创建一个对象的操作：
1) 为该对象分配内存
2) 在分配好的内存上构造该对象
C++delete删除一个对象的操作
1) 对用对象的析构函数
2) 释放分配给对象的内存

1、避免使用malloc()和free()
C函数malloc和free只做了一半的工作。malloc分配内存，free释放内存。malloc并不调用构造函数，而free也不调用析构函数（参考mallocVersusNew.cpp）
2、避免显式调用new和delete
3、立即将显式资源分配的结果交给一个管理者对象（管理者对象可以是std::unique_ptr或者std::shared_ptr），当不遵循这些规则是，就会有未定义行为的潜在危险（参考standaloneAllocation.cpp）
4、在一条表达式语句中最多进行一次显式资源分配
对于以下函数：
```cpp
void func(std::shared_ptr<Widget> sp1 , std::shared_ptr<Widget> sp2){
    ...
}
```
进行以下函数调用时：
```cpp
func(
    std::shared_ptr<Widget>(new Widget(1)),
    std::shared_ptr<Widget>(new Widget(2)),
)
```
该函数不是异常安全的，可能会导致内存泄漏：
原本初始化的顺序：
1) 为Widget(1)分配内存
2) 构造Widget(1)
3) 为Widget(2)分配内存
4) 构造Widget(2)
但是经过编译器优化后可能出现的一种情况（**一次分配两个Widget的内存很可能比两次分配单个Widget内存要快**）：
1) 为Widget(1)分配内存
2) 为Widget(2)分配内存
3) 构造Widget(1)
4) 构造Widget(2)
此时若出现一个构造函数抛出一个异常另一个对象内存的内存就不会被释放，此时就会发生内存泄漏
解决办法：使用工厂函数std::make_shared（同理使用到std::unique_ptr的情况可以使用std::make_unique工厂函数），它保证了如果有异常抛出，函数调用不会产生可察觉的副作用
**而对于C++17，因为已经保证了求值顺序--函数调用里的子表达式会在一项求值完成后再进行下一项（不过哪个先哪个后仍然没有明确规定），所以上面的代码片段将不会再导致内存泄漏**

# 智能指针
## 基本用法
1、用unique_ptr或shared_ptr表示所有权
1) std::unique_ptr：独占所有者。它不可以被拷贝，只能被移动。
2) std::shared_ptr：共享所有者。当拷贝或者拷贝赋值某个共享指针，它的引用技术增加；当删除或者重置某个共享指针，它的引用计数则减少。当引用计数变为0时，其底层资源将被删除。
3) std::weak_ptr：对std::shared_ptr所管理资源的非占有的引用。它并不是智能指针。它只有一个引用，该引用指向被std::shared_ptr做管理的对象。不可透明地访问底层资源。通过对std::weak_ptr调用lock成员函数，可以从某个std::weak_ptr创建出一个shared_ptr

```cpp
auto sharedPtr1 = std::make_shared<int>(1998); // 引用计数为1
std::weak_ptr<int> weakPtr(sharedPtr1);        // 引用计数为1
auto sharedPtr2 = weakPtr1.lock();             // 引用计数为2
```
2、除非共享所有权，否则能用unique_ptr就别用shared_ptr（需要管理它的引用计数并且需要分配额外的内存来维护其控制块。为了管理被控制对象的生存期，控制块是必须的，当需要共享所有权时，只需要做一次共享资源的分配，因此可以节省内存和时间）
**不要为了做拷贝而贪图方便地使用std::shared_ptr。std::unique_ptr不可以被拷贝，但仍可以被移动，参考，oveUniquePtr.cpp**
3、使用make_shared()创建shared_ptr和使用make_unique()创建unique_ptr
理由：
1) 异常安全
2) 该理由仅对std::shared_ptr成立：
对于以下std::shared_ptr的创建：
```cpp
// 发生两次内存分配：1) new int(1998) 2) std::shared_ptr的控制块
auto sharedPtr1 = std::shared_ptr<int>(new int(1998));
// 将上述的两次内存分配变成一次且分配出来的对象（new int(1998)）和控制块彼此相邻，访问会更快
auto sharedPtr2 = std::make_shared<int>(1998);
```
4、使用std::weak_ptr来打破shared_ptr形成的环（参考cycle.cpp）
**如果std::shared_ptr互相引用就会形成环状引用。一个双向链表会形成环但是如果使用std::shared_ptr来实现那么引用记数永远不会为零最终导致内存泄漏**

## 函数参数
1) func(std::unique_ptr<Widget>)：func拿走所有权
2) func(std::unique_ptr<Widget>&)：func要重装Widget
3) func(std::shared_ptr<Widget>)：func共享所有权
4) func(std::shared_ptr<Widget>&)：func可能要重装Widget
5) func(const std::shared_ptr<Widget>&)：func可能保有一份引用计数
**重装：表示函数会修改引用参数的智能指针的内容，来指向一个不同的对象**

1、只在显式表示生存期语义时以智能指针作参数（参考lifetimeSemantic.cpp）
**若只使用智能指针的底层资源，应该以原始指针或引用作为函数参数**

在某个共享指针sharedPtr上调用reseat时，复杂的工作流程会在幕后发生：
1) 如果你在sharedPtr上调用reseat而不殆参数，引用计数会-1。之后，sharedPtr不再是资源所有者。
2) 如果调用reseat时带了个参数，并且引用计数至少是2，会得到两个独立的共享指针，它们拥有不同的资源
3) 如果调用reseat时引用计数变为0，那么无论是否带参数，其资源均会被释放

对于std::unique_ptr：
1) 若要获取所有权，必须按值来接受相应std::unique_ptr，调用方必须移动std::unique_ptr
2) 若想要重装，这种情况下应当按非const引用来传入std::unique_ptr
当std::unique_ptr重装时，会构造新值，析构旧值

从函数角度看std::shared_ptr：
void share(std::shared_ptr<Widget>)：在函数的生存期内，是这个Widget的共享所有者。在函数开始时，增加引用计数；在函数结束时，减少引用计数；因此只要函数中在使用Widget，它就一直活着
void reseat(std::shared_ptr<Widget>&)：由于没有改变引用计数，所以不是Widget的共享者，并不能保证Widget的存活，但是可以重装资源
void mayShare(const std::shared_ptr<Widget>&)：也许会分享该资源。根据函数逻辑，如果需要共享，函数可以通过拷贝shared_ptr将其保留下来，如果共享最终不需要的化，也不会有额外开销（因为函数只要求一个const引用的参数）

2、不要传递从智能指针别名（引用）中获取的指针或引用
由于智能指针别名并不是所有者（引用计数不会增加），可能会造成悬空指针（并不能保证获取的这个智能指针保持存活）
**只有实际持有共享资源所有权的一部分时，才可以访问资源**
