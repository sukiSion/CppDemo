并发和并行：
并发：多个任务的执行可重叠。并发是并行的超集
并行：对个任务在同一时间运行。并行是并发的子集

# 通用规则
1、假设代码作为多线程程序的一部分来运行（主要针对库代码）
摆脱数据竞争的方法：
1) 使用锁来保护整个临界区域：粗粒度的锁定方法，通常不应该像这样使用粗粒度的锁
2) 使用锁来保护发生可能发生数据竞争的整个函数：最粗粒度的方法，因为整个函数都被锁定了
3) 将可能发生的数据竞争变量设置为thread_local：最好
2、避免数据竞争（参考dataRace.cpp）
**数据竞争：至少有两个线程在异步的情况下访问一个非原子的共享变量，并且至少有一个线程试图修改该变量**
**共享、可变的状态是发生数据竞争的必要条件，也就说只有同时存在共享、可变两个条件才会产生数据竞争**
3、尽量减少对可写数据的显式共享
共享数据应该是不变的，需要线程安全的方式初始化常量共享数据
1) 在启动线程之前初始化数据
2) 使用常量表达式，因为它们在编译期被初始化
3) 将函数std::call_once与函数std::once flag结合起来使用。可将重复初始化内容放入函数onlyONceFunc中。C++运行期保证这个函数只会成功运行一次
```cpp
std::once_flag onceFlag;
void do_once(){
    std::call_once(onceFlag , []{
        std::cout << "Important initialization" << '\n';
    });
}
```
4) 使用具有块作用域的静态变量，因为C++11的运行时保证它们会以线程安全的方式初始化
4、从任务（而不是线程）的角度进行思考
从C++11开始，任务作为一个特别术语，它由诺值（promise）和期值（future）使用。
诺值产生期值可以异步获取的值。诺值和期值可以在不同的线程中运行，然后通过安全的数据通道相连接。
**线程和期值/诺值对的区别：线程是关于应该如何计算的；任务是关于应该计算什么**
对于：
```cpp
// 线程
int res;
std::thread t([&]{res = 3 + 4;});
t.join();
std::cout << res << '\n';

// 任务
auto fut = std::async([]{return 3 + 4;})
std::cout << fut << '\n';
```
1) 线程t使用共享变量res来提供结果。与此相反，std::async的诺值会建立一个安全的数据通道，并用它把结果传递给期值fut。这种数据共享意味着，对于线程t，必须保护res
2) 对于线程，需要明确进行创建。对于诺值std::async，则不一定会自动创建线程。指定应该计算什么，而不是应该如何计算。如果有必要，C++运行时会决定是否要创建线程。
**线程注重过程，期值/诺值注重结果**
5、不要使用使用volatile进行同步
**C++的volatile与Java和C不同，C++的volatile用于特殊对象，不允许对进行优化读或写操作，主要用于嵌入式，C++中的原子量为std::atomic**
6、只要可行，就使用工具来对并发代码进行验证（参考conditionVariablePingPong.cpp）
1) 动态代分析工具ThreadSanitizer：提供全局信息，检测程序的执行是否存在数据竞争
2) 静态代码分析工具CppMem：深入理解代码里的小片段，大多时候会包括原子量，也提供非常精确的分析，使得对C++内存模型有深刻的了解（参考dataRaceOnX.cpp）
**http://svr-pes20-cppmem.cl.cam.ac.uk/cppmem/index.html**

# 关于并发
## 锁
1、使用RAII（lock_guard），永远不要直接使用lock()/unlock()
**RAII关键思想：将资源的生存期与局部变量的生存期绑定**
2、使用std::lock()或std::scoped_lock来获取多个互斥量
**如果一个线程同时需要多个互斥量，那么必须非常小心，始终以相同的顺序锁定互斥量（参考lockGuardDeakLock.cpp）**
3、绝不在持有锁的时候调用未知代码（比如回调函数）
**可以使用将回调函数使用局部变量引用，这样避免了数据竞争且可以在没有同步机制的情况下调用回调函数，且持有锁的时间能够减少到最低限度**

## 线程
1、将汇合thread（thread.join()）看作一个有作用域的容器，将thread看作一个全局容器（子线程可以使用创建它的外围作用域的所有变量）
**必须汇合（join）或分离（detach）子线程，否则会在子线程的析构函数中得到std::terminate**
1) 调用thread.join()时，当前线程会等待所有子线程执行完毕，thread.join()是一个同步点。
2) 调用thread.detach()不会等待，因此它并不是一个同步点。所以会出现被创建的子线程比作为创建者的线程存活得更久。因此外围作用域内的变量可能不再有效。
2、优先选择std::jthread而不是std::thread
**std::jthread在std::thread基础上会在析构时自动汇合（join），防止因为忘记汇合线程而导致的程序意外终止**
3、不要对线程调用detach()（参考threadDetach.cpp）
**竞争条件：竞争条件是这样一种场景，其中操作的结果取决于某些独立操作时如何交错的**

## 条件变量
1、不要再没有条件是wait（正确使用条件变量参考conditionVariable.cpp）
否则存在以下两个问题：
1) 丢失唤醒：发送方在接收方开始等待之前发送了通知，结果通知丢失。（死锁的产生，由于发送方已经发送了通知，这就导致接收方正在等待一些永远不会发生的事情）
2) 虚假唤醒：即使没有发送通知，接收方也可能被唤醒。至少POSIX线程和Windows API会是这些现象的受害者
**条件变量：一个线程准备好了一些东西，并向等待它的另一个线程发送通知**

## 数据共享
1、在线程之间传递少量数据时使用值传递，而不是引用或指针
两个好处：
1) 没有共享，不可能存在数据竞争。
2) 不需要关心数据的生存期。
**C++ Code Guidelines指出以4 * sizeof(int)为临界点，小于应该按值传递，而大于应该按引用或指针传递**
2、要在不相关的thread之间分享所有权，请使用share_ptr
“不相关”：该对象没有数据竞争
**如果不释放共享对象的内存，则会发生内存泄漏（参考threadSharesOwnership.cpp），若delete多次则会产生未定义行为**

## 资源
使用并发的主要原因之一是性能。
使用线程时需要消耗资源：时间和内存。资源的使用从创建开始，然后随着上下文切换从用户空间到内核空间，并以线程销毁而结束。此外，线程有它自己的状态，需要分配和维护
1、尽量减少上下文切换
2、尽量减少线程的创建和销毁
**std::thread是对原生线程的简单封装**
3、尽量减少临界区内的时间占用（只对有可能进行数据竞争的最小范围进行锁定）
比如：
```cpp
void setDataReady(){
    std::lock_guard<std::mutex> lck(mut);
    dataReady = true;
    std::cout << "Data prepared" << '\n';
    condVar.notify_one();
}
```
互斥量在函数开始时被锁定，在函数结束时被解锁，这种锁定是没必要的，只有dataReady = true;必须受到保护
std::cout是线程安全的，C++11标准保证每个字符都按照原子步骤和正确的顺序写入，其次，通知condVar.notify_one()是线程安全的
改进后：
```cpp
void setDataReady(){
    {
        std::lock_guard<std::mutex> lck(mut);
        dataReady = true;
    }
    std::cout << "Data prepared" << '\n';
    condVar.notify_one();
}
```

## 被忽视的危险
1、记得给你的lock_guard和unique_lock起名字（参考myGuard.cpp展示lock_guard概念行为）
**如果没有起名字，就代表只是创建一个临时量，创建以后立即销毁，lock_guard和unique_lock会自动锁定其互斥量和构造函数，并在析构函数中自动解锁，如果没起名字就会发生自动锁定后立即解锁**

## 关于并行
**优先使用STL的并行算法，而不是用线程手写解决方案**
在C++17许多STL算法可以使用所谓的执行策略，通过使用执行策略，可以指定该算法是顺序运行、并行运行hi爱是并行向量化运行
1) std::execution::seq：顺序执行
2) std::execution::par：在多个线程上并行地运行该算法
3) std::execution::par_unseq：在多个线程上并行运行该算法，并允许单个循环的交错。
**向量化std::execution::par_unseq代表现代处理器指令集和SIMD（单指令多数据）扩展。SIMD使处理器能够对多个数据上并行地执行同一个操作**

# 消息传递
1、使用future从并发任务返回值
2、使用async()生成并发任务
任务：是一种C++式的在线程之间传递消息的方式。消息可以式值、异常或者通知。
任务由诺值（std::async、std::packaged_task、std::promise）和期值两部分组成。诺值创建消息，期值异步地进行接收

## 发送值或异常
参考promiseFutureException.cpp

## 发送通知
大多数情况下，诺值和期值时比条件变量更安全的选择（参考promiseFutureSynchronize.cpp）
**与诺值和期值相比，条件变量优势时可以使用条件变量来多次同步线程（每次条件变量被通知且符合条件后都会进行同步），而诺值和期值只能发送一次通知。而如果只为单次同步使用条件变量，那么要把条件变量用对比用诺值和期值难得多。一对诺值和期值不需要锁，不会出现虚假唤醒和丢失唤醒，也不需要临界区或额外的条件判断**

# 无锁编程
并发和并行的规则是针对非专家的。无所编程是一个仅面向专家的主题
1、除非绝对需要，否则不要使用无锁编程
2、不要轻信硬件/编译期组合
**当你违反序列一致性时，你的直觉也大概率会出问题（参考sequentialConsistency.cpp和relaxedSemantic.cpp）**
序列一致性意味着：
1) 每个线程按照指定的顺序执行操作
2) 所有线程上的所有操作都有一个全局顺序。（每个线程看到的所有操作都以相同的顺序执行）
