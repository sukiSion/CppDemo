# 概要规则
1、class和struct之间的语法差异：
在结构体中所有成员默认为public，而在类中所有成员是private的
结构体的继承默认为public，类的基类默认为private
2、把相关的数据组织到结构（struct或者class）中
3、当类具有不变式时使用class，如果数据成员可以独立变化，则使用struct
不变式：用于约束类的实例的不变式。成员函数必须是这个不变式保持成立。不变式约束了类的实例的可能取值
4、在类中体现出接口和实现之间的区别
类的公开成员函数时类的接口，私有部分则是实现
5、仅当函数需要直接访问类的内部表示时，才把它变成成员（运算符=、()、[]、->必须是类的成员）
6、将辅助函数与它们支持的类放在同一个命名空间中，因为它是类的接口的一部分，与成员函数不同，辅助函数不需要直接访问类的内部表示
7、不要在一条语句里定义类或枚举同时声明该类型的变量
8、如果在任何非公开成员，就使用class而不是struct
9、尽量减少成员的暴露

# 具体类型
具体类型：“最简单的一种类”，常常被称作值类型，不属于某个类型层次结构的一部分
规范类型：“行为类似与int的类型”，因此它必须支持拷贝和赋值、相等比较以及可交换
一个规范类型X行为上像int支持下列操作：
1) 默认构造：X()
2) 拷贝构造：X(const X&)
3) 拷贝赋值：operator = (const X&)
4) 移动构造：X(X&&)
5) 移动赋值：operator = (X&&)
6) 析构：~X()
7) 交换操作：swap(X& , X&)
8) 相等运算符：operator == (const X& , const X&)
1、优先使用具体类型而不是类层次结构：具类的类型更容易实现，更小且更快
2、让具体类型规范化

# 构造函数、赋值运算符和析构函数
1) 默认构造函数：X()
2) 拷贝构造函数：X(const X&)
3) 拷贝赋值运算符：operator = (const X&)
4) 移动构造函数：X(X&&)
5) 移动赋值运算符：operator = (X&&)
6) 析构函数：~X()
对于“六大”，可以明确使用 = default来要求编译器提供它们，或者用 = delete来删除它们
1、如果能避免定义默认操作，那就这么做（“零法则”）
2、如果定义或=delete了任何默认操作，就对所有默认操作都进行定义或 =delete
特殊成员函数之间的依赖关系：
1) 当定义任何构造函数时，默认构造函数就没有了
2) 当用 = default 或 = delete定义或删除默认构造函数时，其他特殊函数不受影响
3) 当用 = default 或 = delete定义或删除析构函数、拷贝构造函数或者拷贝赋值操作符时，编译器不会生成移动构造函数和移动赋值运算符。移动操作将退回至拷贝操作
4) 当用 = default 或 = delete定义或删除移动构造函数或移动操作运算符时，只能得到定义的 = default或 = delete的移动构造函数或移动赋值运算符。拷贝构造函数和拷贝赋值运算符将被设为 = delete，因此调用一个拷贝操作，如拷贝构造函数或拷贝赋值，将导致编译错误
3、让默认操作保持一致（不能假设编译器生成的特殊成员函数和自己实现的具有相同的语义）
编译器生成的拷贝构造函数或拷贝赋值运算符也使用浅拷贝

## 构造函数
1) 构造函数通用
2) 默认构造函数
3) 单参数构造函数
4) 成员初始化
5) 特殊构造函数，如继承或委托构造函数
**不要在构造函数中调用虚函数**

## 构造函数通用
1、如果类有不变式，就定义构造函数
2、构造函数应当创建完全初始化的对象（类不应该定义类似init() 成员函数，必然就是自找麻烦）
当一个类的所有构造函数有共同的操作时，请使用委托构造函数
3、如果构造函数无法构造出优先对象，则应抛出异常

## 默认构造函数
1、确保可拷贝的（值类型）类有默认构造函数（当类的实例缺少有意义的默认值时，该类就不需要默认构造函数）
2、不要定义仅初始化数据成员的默认构造函数，而应使用成员初初始化器（参考classMemberInitializerWidget.cpp）
添加新成员只需要在类的主体中添加初始化而不必在所有的构造函数中添加
不需要考虑将初始化器按正确的顺序放在构造函数中
在类的主体中定义默认行为，明确定义的构造函数只用来改变默认行为
3、默认情况下，把单参数的构造函数声明为explicit（参考convertingConstructor.cpp）

## 成员的初始化
1、按照成员声明的顺序定义和初始化成员变量（参考memberDeclarationOrder.cpp）
2、在使用常量来初始化时，优先选择类内初始化器，而不是构造函数的成语初始化，虽然类内初始化规定了一个对象，但构造函数可以改变这一默认行为
3、在构造函数里优先使用初始化而不是赋值
1) 不会因为忘记赋值使用未初始化的成员
2) 初始化可能更快，并且绝不会比赋值慢

## 特殊构造函数
1、使用委托构造函数来表示类的所有构造函数的共同动作
委托构造函数：把它的工作委托给同一个类的另一个构造函数
2、使用继承构造函数将构造函数导入不需要进一步显式初始化的派生类中
继承的构造函数保留了它们在基类中定义的所有特性，如访问说明符或属性explicit和constexpr
如果派生类中有自己的成员，它们不会被初始化，除非它们有类内初始化器

## 拷贝和移动

### 赋值
1、使拷贝赋值非virtual，以const& 传参，并返回非const的引用
example: vector& operator=(const vecotr& other);
2、使移动赋值非virtual，以&& 传参，并返回非const的引用
example: 
vector& operator=(vecotr&& other); // c++17前
3、使移动操作（移动构造函数和移动赋值运算符）noexcept，一个noexcept声明的函数对编译器来说是个优化机会
vector& operator=(vecotr&& other) noexcept; // c++17起
vector(vector&& other) noexcept; // c++17起
4、使拷贝和移动赋值对自赋值安全（自赋值安全：x = x 不应该改变x的值）
自动生成的拷贝移动赋值运算符对自赋值也是安全的，使用自赋值安全的类型自动生成的拷贝移动赋值运算符也是如此
**对于自赋值安全的拷贝移动赋值运算符，请不要做多余的自赋值检查（if(this == &a) return *this;）**
5、拷贝转操作应该进行拷贝，
1) 在拷贝之后（a = b），a和b必须相同（a == b）
2) 拷贝可深可浅。深拷贝意味着对象a和b之后使相互独立的（值语义）。浅拷贝意味着对象a和b之后共享一个对象（引用语义）
6、移动操作应该进行移动，并使源对象处于有效状态
C++标准要求被移动的对象之后必须处于一个未指定但有效的状态。通常情况下，这个被移动的状态使移动操作源对象的默认状态
7、多态类应当抑制公开的拷贝/移动操作
多态类是定义或继承了至少一个虚函数的类（可能会以切片而告终，参考sliceVirtuality.cpp）
**切片：赋值或者初始化过程中拷贝一个对象，只得到该对象的一部分**
拷贝的情况下，编译器使用了声明的类型，即静态类型。若使用间接手段（引用或者指针），那么使用当前类型，即动态类型
对于多态类：
若需要进行深拷贝，最好使用虚clone()函数
如果类里面有数据成员，把拷贝移动操作设为protected
若没有数据成员则可以直接使用=delete删除拷贝移动操作

## 析构函数
1、如果一个类在对象销毁时需要明确的动作，那就定义析构函数
2、类获得的所有资源都必须在该类的析构函数中释放
3、如果类里有原始指针或引用，请考虑他是否有所有权
指针既可以表示所有权也可以表示借用，所有权不明确会造成一下情况：
1) 删除不拥有所有权的对象的一个指针：双重删除
2) 漏删拥有所有权的一个指针：内存泄漏
4、如果类有具有所有权的指针成员，请定义析构函数
注：智能指针支持六大特殊成员函数：若在一个类中使用std::share_ptr，并不会对该类施加任何限制。反过来若在类的定义中使用unique_ptr，则会禁用拷贝语义（参考classWithUniquePtr.cpp）
5、基类的析构函数应该要么是public且virtual，要么是protected且非virtual
如果基类有public且virtual的析构函数，可以通过基类的指针来销毁派生类的实例，引用也是如此
如果基类的析构函数是protected，就不能用基类指针或引用来销毁派生对象（需要直接调用派生对象）
如果基类的析构函数是private，无法从该类进行派生
如果基类的析构函数是protected，能从该类派生出子类，然后只使用子类
6、析构函数不能失败
7、使析构函数noexcept（用户定义或隐式生成的析构函数默认为noexcept，如果类中的某个成员或基类拥有无noexcept保证的析构函数，那么这个类的析构函数也没有noexcept保证，若无法确定是否所有成员都有noexcept的析构函数，需要显示地将析构函数声明为noexcept）
noexcept调用链：std::terminate -> srd::terminate_handler -> std::abort()
noexcept表达：
1) 函数抛出任何异常
2) 函数若抛出异常让程序终止
**应该明确地将析构函数声明为noexcept**

## 其他默认操作
1、如果需要明确使用默认语义，则使用 = default
如果定义了五个特殊成员函数中（除默认构造函数之外的其他所有特殊成员函数）的任何之一，就必须将它们全部都定义一下
2、当想要禁用默认行为（且不需要替代方法）时使用 = delete（参考immortal.cpp）
**几乎所有来自线程API的类型的拷贝构造函数都被设置为delete，线程API类型不允许拷贝**
3、不要在构造函数和析构函数中调用虚函数
虚调用机制在构造函数或析构函数中被禁用,所以会得到非虚的调用（参考virtualCall.cpp）
4、对于类值类型，考虑提供一个noexcept的交换函数
**对已经提供了swap成员函数的类，应再提供一个非成员函数的swap函数，若不提供非成员的swap函数，那么需要交换的标准库算法（std::sort和std::rotata）将退回到std::swap模板**
```cpp
std::swap模板：
template<typename T>
void std::swap(T& a , T& b) noexcept{
    T tmp(std::move(a));
    a = std::move(b);
    b = std::move(tmp);
}
```
5、使 == 对操作数的类型对称，并使其noexcept（注意类的单参数构造函数要使用explicit，否则会出现类似MyInt(5) == 5的现象，因为5会自动转化为MyInt(5)；另一个方法是提供一个友元函数支持被自动转化类型和定义的类型比较）
6、当心基类上的 ==（参考equalityOperatorHierarchy.cpp），该结构适用于!=、<、<=、>和=>

# 类层次结构
接口继承（公有继承）：将用户和实现分开，允许派生类增加或改变基类的功能而不影响基类的用户
实现继承（私有继承）：在典型情况下，派生类通过调整基类的功能来提供其功能
突出例子：适配器模式：将现有的接口改编成一个新接口，适配器使用了实现的私有继承和对新接口的公有继承。新的接口使用现有的实现来为用户提供服务

## 一般性规则
1、（仅）使用类的层次结构来表达具有内在层次结构的概念
接口隔离原则：任何客户端（如派生类）都不应该被迫依赖于它不使用的成员函数，将那些太大、由太多成员函数组成的接口分割成更小、更具体的接口
2、如果基类被当作接口使用，那就把它变成抽象类
3、当需要完全分离接口和实现时，以抽象类作为接口

## 类的设计
1、抽象类通常不需要构造函数（抽象基类没有任何数据，因此不需要声明构造函数）
2、虚函数应该指定virtual、override或者final三者之一
virtual：声明虚函数会在派生类中被覆盖
override：证实函数是虚函数，并覆盖基类里的虚函数
final：证实函数是虚函数，且不能再被派生类中的成员函数所覆盖
**只在声明一个新的虚函数时使用virtual。只在声明一个覆盖函数时使用override。只在声明最终覆盖函数时使用final**
3、若要对多态类进行深拷贝，应使用虚函数clone，而不是公开的拷贝构造和赋值
在派生类中通过所谓的协变返回类型（允许覆盖成员函数并返回被覆盖成员函数的返回类型的派生类型）来返回派生类（参考cloneFunction.cpp）
4、不要无缘无故地把函数变成virtual
1) 增加了运行时间和对象代码的大小
2) 因为它可以在派生类中被覆盖，更容易出问题

### 数据成员的访问说明符
通常情况下一个类的所有数据成员的访问说明符都相同：所有数据成员要么全部属于public，要么全部属于private
1) 如果数据成员上面没有不变式，则用public。使用struct关键字
2) 如果数据成员上有不变式，则用private。使用class关键字
1、避免无价值的取值和设值函数
2、避免protected数据
1) 是否需要实现一个构造函数初始化protected数据
2) 实际价值？
3) 修改protected数据，谁会受到影响
由于protected数据是类层次结构范围内的一种全局数据，这并不好
3、确保所有的非const数据成员都具有相同的访问级别（由于使用protected不好，所以应该使数据都使private或者public）
1) 一个对象的数据成员不一定表示该对象的不变式
2) 不表示对象不变式的非const数据应该声明为public
3) 非const的private数据成员用于对象不变式
4) 一个具有不变式（受到某种限制）不能使用底层类型的所有值，反之能使用所有值的数据成员不是不变式，应为public
5) 不应该在一个类中混合使用表示以及不表示不变式的数据成员

### 多重继承
使用场景：
1) 将接口继承和实现继承分开
2) 实现多个不同接口
1、在设计类的层次结构时，要区分实现继承和接口继承
实现继承：扩展现有的功能，从而支持功能（基类有数据成员或者已经有函数实现）
接口继承：接口和实现的分离，派生类的修改可以不影响基类用户（基类只有纯虚函数）
用接口分层的稳定接口，实现继承的代码重用：
1) 双重继承
2) PImpl惯用法
2、使用多重继承来表示多个不同的接口（根据接口某些方面进行细分）
由于提供一个只有纯虚函数组成的纯接口具体类必须实现所有的函数，若接口过于宽泛，这个类可能就需要实现它不需要的或者没有意义的功能
**example: class iostream: public istream , public ostream{} //由于接口的细分，大大简化了**

### 典型陷阱
1、使用using为派生类以及基类创建重载集（参考overloadSet.cpp）
“遮蔽”：若不使用using声明，派生类的成员函数会隐藏整个重载集，从而导致选择一个看起来不是最佳匹配的重载
2、不要为虚函数和它的覆盖函数提供不同的默认参数（参考overrider.cpp）

## 访问对象
### dynamic_cast
dynamic_cast: 沿继承层级向上、向下及侧向，安全地转换到其他类的指针和引用
1、在穿越类层不可避免时，应使用dynemic_cast（它的职责）
2、当“找不到所需的类”被视为错误时，须对引用类型使用dynamic_cast
对引用使用dynamic_cast失败时会出现std::bad_cast异常
3、当“找不到所需的类”被视为有效选择时，需对指针类型使用dynamic_cast
对指针使用dynamic_cast失败时会得到一个空指针
（2、3参考badCast.cpp）
4、永远不要把指向派生类对象数组的指针赋值给指向基类的指针（退化成指针将派生类指针转换为基类指针，而后面进行指针算术的时候就会出错，本来ptr+1对派生类数组来说就是指针值加上派生类内存大小值刚好能取得下一个对象地址，但是指向基类后加上的就是基类的内存大小值，最后导致无效对象的访问）

# 重载和运算符重载
1) 函数
2) 成员函数
3) 模板函数
4) 运算符

## 常规用法
1、应当对带有常规含义的操作使用运算符
1) 比较操作：==、!=、<、<=、>和>=
2) 算数操作：+、-、*、/和%
3) 对象访问：-> 、一元*和[]
4) 对象赋值：=
5) 输入和输出操作：<<、>>
2、对于对称运算符，应采用非成员函数（一般来说，在类内实现对称运算符是不可能的，参考MyInt.cpp）
3、避免隐式转换运算符（若重载了bool运算符且不设置为explicit，当使用该对象进行算术操作时将会进行bool到int的整型提升false-> 0 ，true->1，参考implicitConversion.cpp）
4、重载的操作应当大致等价
5、仅对大致等价的操作进行重载
比如：
```cpp
void print(int a);
void print(const string&);
...
print(5);
```
由于print()函数都是大致作用：显示对应的类型，所以进行重载
反之：
```cpp
std::string translate(const std::string& text); // 翻译成英语
Code translate(const Code& code); // 编译代码
```
上述时不等价的操作有相同的名字，这种行为有迷惑性，让人糊涂容易出错
6、在操作数所在的命名空间中定义重载运算符
ADL意味着对于无限定的函数调用，C++在编译时会把函数参数命名空间中的函数也考虑进去
对于运算符，C++编译时也考虑操作数的命名空间。

# 联合体
不应该使用裸联合体，而应该使用std::variant这样的带标签的联合体
裸联合体：
```cpp
union Value{
    int i;
    double d;
};
```
1、使用union来节约内存
2、避免裸联合体（要使用裸联合体，必须跟踪底层类型，参考nakedUnion.cpp）
3、使用匿名union来实现带标签的联合体（由于使用匿名union来实现带标签联合体非常复杂，故事用了c++17中的std::variant来演示，参考variant.cpp）
