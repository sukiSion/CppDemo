# 关于接口
1、使用函数对象将操作传递给算法
STL算法的行为通常可以通过一个可调用对象来调整（参考functionObjects.cpp）
**可调用对象：函数、函数对象和lambda表法式**
函数对象的优势：
1) 性能
2) 表法力
3) 状态（参考sumUpFunctionObject.cpp），lambda表法式也可以由状态（参考sumUpLambda.cpp）
2、使用模板别名来简化写法并隐藏实现细节
```cpp
template<typename T>
void user(T& c){
    // ...
    typename container_traits<T>::value_type x; // 不好，过于冗长
    // ...
}
```
等效于
```cpp
template<typename T>
// 给模板起一个别名，后面依旧可以使用泛型的方式来进行使用，比如value_type<T>
using value_type = typename container_traits<T>::value_type x;
void user(T& c){
    // ...
    value_type<T> x;
    // ...
}
```
3、优先使用using而不是typedef来定义别名
原因：
1) 在使用时using最先出现
2) using用起来感觉于auto非常相似
3) using可以很容易地用于模板别名
4、使用函数模板来推导类模板的参数类型（在可行时）
**函数模板可以从其函数参数中推导出其模板参数，从C++17开始，编译期在很多情况下不仅可以从函数参数中推导出模板参数，还可以从构造函数的参数中推导出模板参数（参考templateArgumentDeduction.cpp）**
5、要求模板参数至少为规范或半规范（参考semiRegular.cpp）
半规范类型支持六大操作还必须可交换：
1) 默认构造函数：X()
2) 拷贝构造函数：X(const X&)
3) 拷贝赋值运算符：X& operator = (const X&)
4) 移动构造函数：X(X&&)
5) 移动赋值运算符：X& operator = (X&&)
6) 析构函数：~X()
7) 可交换：swap(X& , X&)
规范：一个相等比较的半规范类型时规范的
1) 等价运算符：operator == (const X& , const X&)
2) 不等运算符：operator != (const X& , const X&)
**STL容器和算法在规范数据类型上运行良好，常用但不规范的类型：引用，它甚至不是半规范类型，因为它不能被默认构造**
6、避免使用有常见名称的高可见度无约束模板（参考argumentDependentLookup.cpp）
实参依赖查找（ADL）：是一组用于查找非限定函数名的规则。非限定函数名称会导致在其参数所在的命名空间中进行额外的查找
非限定名称：指没有作用域运算符（::）的函数。
7、如果编译器不支持概念，请使用enable_if来模拟（参考enable_if.cpp）
**C++标准规定：当使用推导出的类型替代模板参数失败时，该特化将从重载集中丢弃而不是引起编译错误**

# 元编程
元编程是编译期编程。主要驱动力是常量表达式。

## 模板元编程
1、只有在真正需要的时候使用模板元编程
2、使用模板（通常是模板别名）在编译期计算类型

### 编译期计算
计算数字的阶乘就是模板元编程里的“Hello World”（参考factorial.cpp）

### 编译期类型操纵
从参数中移除常量属性（参考removeConst.cpp）

### 更多“元”
在运行期使用的是数据和函数，在编译期使用元数据和元函数。
元数据：元函数在编译期使用的值有三种类型
1) 类型，比如int或double
2) 非类型，比如整型、枚举项、指针或引用
3) 模板，比如std::vector或std::deque
元函数：在编译期执行的函数
**类型在模板元编程中式用来模拟函数的。根据原函数的定义，可以在编译期执行的constexpr函数也是元函数。约定熟成：如果元函数返回一个值，则它被称为value；如果返回一个类型，则它被称为type**

### 函数和元函数
区别（参考power.cpp）：
参数：函数参数放在(...)里面，元函数参数放在<...>里面。这结果同样适用于函数和元函数的定义。函数适用圆括号，元函数使用尖括号。每个元函数都会产生一个新类型
返回值：函数使用return语句，而元函数使用一个静态整常量值。
**也有函数作为普通函数和元函数的情况（参考powerHybrid.cpp）**

## 类型特征库
类型特征库是C++11的一部分，在编译期支持类型检查、类型比较和类型修改
1、优先使用标准库的模板元编程工具
### 类型检查（参考primaryTypeCategories.cpp）
**许多元函数（模板类型），名字里有“trivially”意味着编译期提供的特殊非静态成员函数不需要实际地做任何事情（默认构造函数和析构函数），或者只需要进行简单的内存复制（其他特殊非静态成员函数）**

### 类型比较
类型特征库支持三种比较（参考compare.cpp）：
1) std::is_base_of<Base , Derived>
2) std::is_convertible<From , To>
3) std::is_same<T , U> 
类型特征库的功能：
1) 类型特征库中的函数是元函数，因为它们在编译期运行。元函数是类模板。
2) 尖括号<...>中元函数的参数是元数据。在这种情况下，元数据就是类型。
3) 函数的返回值是::value。value是一个静态constexpr数据成员。从C++17可以使用_v的后缀元函数（类模板）代替std::is_xxx<...>::value获取结果。

### 类型修改
类型修改属于模板元编程的领域，因此类型特征库支持类型修改。
类型特征库提供了许多元函数来操作类型。
可以使用::type来请求元函数类型，从C++14可以使用_t的后缀元函数来获取类型

#### 正确性
可以使用类型特征库来实现Integral、SignedIntegral和UnsignedIntegral等概念
```cpp
template<typename T>
concept Integral = std::is_integral<T>::value

template<typename T>
concept SignedIntegral = Integral<T> && std::is_signed<T>::value

template<typename T>
concept UnsignedIntegral = Integral<T> && !SignedIntegral<T>
```
这意味可以让算法更加安全（参考gcd2.cpp）


#### 性能优化
类型特征库的思想：编译期分析使用的类型并决定应创建的代码
对于标准模板库的算法std::copy、std::fill或std::equal，这意味着在某种情况下，该算法会被逐一应用到范围内的每个元素或整个内存上。在其他情况下会使用C函数，比如memcpy、memmove、memset或memcmp这样的算法会更快。
memcpy和memmove之间的小区别是，memmove可以用来处理重叠的内存区域

## 常量表达式
1、使用constexpr函数在编译期进行值计算
使用constexpr的常量表达式有三种形态：
变量：
1) 是隐式常量
2) 必须有常量表达式初始化
函数：
1) 可以调用其他constexpr函数
2) 可以有变量，变量必须初始化
3) 可以使用条件表达式或循环
4) 是隐式内联
5) 不可以有static或thread_local数据
6) 不可以使用异常处理
用户定义类型：
1) 必须有一个构造函数，它是一个常量表达式
2) 不可以有虚函数
3) 不可以有虚基类
优点：
1) 可以在编译期求值
2) 让编译器深入了解代码
3) 是隐式线程安全的
4) 可以构造到只读存储器中（能放进ROM）
constexpr函数只能依赖于其他常量表达式。作为constexpr函数，并不意味着该函数在编译期被执行：它意味着该函数可能在编译期被执行。**编译器和优化级别决定了constexpr函数实在编译器还是在运行期运行**
两种情况下constexpr函数必须在编译器运行
1) constexpr函数被用于编译器求值的上下文。这可以是static_assert表达式、模板的实例化或C数组的初始化
2) 在编译器明确请求constexpr函数的值：constexpr auto res = func(5)

#### 模板元编程与constexpr函数的比较
1) 模板元编程在编译期运行，但是constexpr函数可以在编译期或运行期运行。
2) 模板元编程的参数可以是类型、非类型和模板。constexpr函数潜在可以在编译期运行。
3) 模板元编程在编译期没有状态，因此没有什么可修改，这意味着模板元编程时一种纯函数式的编程方式。
4) 在模板元编程中，你不能修改值，而是每次返回一个新的值
5) 在编译期不可通过对变量（如i）增一来控制for循环。因此模板元编程用递归来代替循环
6) 在模板元编程中，条件执行被模板特化所取代

constexpr函数的优点：
除了更容易编写和维护，以及可以在编译期和运行期运行等优点外，constexpr还可以处理浮点数，而模板元编程只能接受整数（C++20之前）

## 模板特化
模板定义了类和函数族的行为。通常特殊参数必须单独处理。为了支持这种情况，可以全特化模板。类模板还可以偏特化。
```cpp

// 主模板
template <typename T , int Line , int Column>
class Matrix;

// 偏特化
template <typename T>
class Matrix<T , 3 , 3>{};

// 全特化
template <>
class Matrix<int , 3 , 3>{};

```
编译器使用以下规则来决定该选择哪个特化：
1) 如果编译器只能匹配到一个特化，那么使用此特化
2) 如果编译器找到多个特化，那么使用其中最特殊的特化。如果这样的结果不唯一，那么编译器会报错。
3) 如果编译器没有找到特化，那么它会使用主模板
**判断A模板比B模板更特殊的方法：A模板是B模板的子集**

## 函数模板的特化与重载
函数模板仅支持全特化，函数重载会开始发挥作用（参考functionTemplateSpecialization.cpp）
**在函数重载的情况下，当函数重载非常合适时，编译器会优先选择函数重载而不是函数模板**
