语句做某事，通常由表达式或语句组成
包含在块作用域中的声明是语句。块作用域是指包含在花括号的内容。

# 通用规则
1、优先使用标准库，而不是其他库和“手工代码”
2、优先使用合适的抽象，而非直接使用语言特性

# 声明
声明是一条语句。声明将名字引入作用域中，并可能引起具名对象的构造

## 名字
1、保持作用域较小
2、在for语句的初始化式和条件中声明名字以限制其作用域
3、常用的和局部的名字要短，不常用的和非局部的名字要长
4、避免看起来相似的名字
5、避免ALL_CAPS（全大写加下划线）风格的名字（可能会发生宏替换）
6、每条声明（仅）声明一个名字
7、使用auto来避免类型名字的多余重复
8、不要在嵌套作用域中复用名字（参考shadow.cpp和shadowClass.cpp）

## 变量及变量初始化
1、始终初始化对象，对于用户定义类型，即使是局部作用域的变量编译器也有可能将其初始化（使用auto）
2、不要在确实需要使用变量（或常量）之前就将其引入
3、在获得可用来初始化变量的值之前不要声明变量
4、优先使用{}初始化语法
{}初始化的优点：
1) 始终可用（参考uniformInitialization.cpp）
2) 克服“最令人烦恼的解析”（参考mostVexingParse.cpp）
3) 防止窄化转换（参考narrowingConversion.cpp）
**在C++17以前使用auto自动类型推导结合使用{}初始化会得到std::initializer_list**
直接初始化：直接使用构造函数的初始化方式，不使用等号，可使用()或{}，如new int(42)和int n{42};
复制初始化；初始化变量时需要使用等号，如int n = 42;
5、不要将同一个变量用于两个不相关的目的
6、使用lambda表达式进行复杂的初始化（尤其是对const变量）

## 宏
1、不要使用宏来操纵程序文本
2、不要把宏当作常量或“函数”使用（参考macro.cpp）
3、对所有的宏名称使用ALL_CAPS命名
4、如果你必须使用宏，请给它们起唯一的名字

# 表达式
1、避免复杂的表达式
2、如果对运算符优先级不确定，那就使用括号
3、保持指针的使用简单明了
**可以使用模板编写边界安全的代码(参考at.cpp)**
4、避免“魔法常量”，采用符号常量
尽量把一些常用数字定义成符号，比如:
```cpp
constexpr int first_month = 1;
constexpr int last_month = 12;
```
5、避免对范围检查的需要（参考sumUp.cpp）

## 指针
1、使用nullptr而不是0或NULL
**nullptr类型指针一方面可以与所有指针进行比较，另一方面可以转换为所有指针**
**nullptr可以显式地基于上下文转换为bool类型，因此可以在逻辑表达式中使用nullptr**
由于模板参数的推导，字面量0或NULL被推导为整数类型，这两个字面量丢失了空指针常量的信息（参考nullPointer.cpp）
2、使用delete[]删除数组，用delete删除非数组对象
3、不要对无效指针解引用（应该使用智能指针）

## 求值顺序
1、避免有未定义求值顺序的表达式
C++17额外保证：
1) 后缀表达式是从左到右进行求值的。这包括函数调用和成员选择表达式
2) 赋值表达式从右到左进行求值。这包括复合赋值，如+=
3) 移位运算符的操作数从左到右进行求值
**有了C++17可以保证每个函数参数在其他函数参数求值之前被完全求值，但是参数的求值顺序仍然是不确定的**
2、不要依赖函数参数的求值顺序（参考unspecified.cpp）
C++17保证的表达式求值顺序：
```cpp
f1()->m(f2()); // 后缀表达式从左到右进行求值
std::cout << f1() << f2(); // 移位运算符的操作数从左到右进行求值
f1() = f(2); 赋值表达式从右到左进行求值
```

## 转换
如有必要请使用显式转换
1、避免转型（参考casts.cpp）
**C风格转型会从static_cast开始，接着是const_cast，最后执行reinterpret_cast**
2、如果必须使用转型请使用具名转型
C++11存在的6种转型：
1) static_cast：在类似的类型之间进行转换，如指针类型或数字类型
2) const_cast：添加或删除const或volatile
3) reinterpret_cast：在指针之间或在整型和指针之间转换
4) dynamic_cast：在同一个类层次种的多态指针或引用之间进行转换
5) std::move：转换为右值引用
6) std::forward：将左值转换为左值引用，或将右值转换为右值引用
3、不要用转型去除const
**如果底层对象是const，试图修改底层对象而用转型去除const的行为是未定义行为**
```cpp
const int constInt = 10;
const int* pToConstInt = &constInt;

int * pToInt = const_cast<int*>(pToConstInt); // 去除const
*pToInt = 12; // 未定义行为
```

# 语句

## 迭代语句
1、在可以选择时，首选基于范围的for语句而不是普通的for语句
2、避免在原始for循环的主体种修改循环控制变量
3、当有一个明显的循环变量时，首选for语句而不是while语句
4、当没有明显的循环变量时，首选while语句而不是for语句
5、优先考虑将循环变量声明在for语句的初始化部分
6、避免使用do while语句和goto语句
7、尽量不要在循环中使用break和continue
8、优先使用算法而不是原始循环（常常可通过lambda表法式进行适配，还可以利用并行或并行加向量化的版本来运行）

## 选择语句
在可以选择时首选switch语句而不是if语句（switch语句通常更加可读，且比if语句更好优化）
1、不要依赖switch语句中的隐式直落行为
在C++17中对于隐式直落行为可以使用[[fallthrough]]来向编译器表明这里故意要直落，否则直落会发生编译器警告
[[fallthrough]]必须在它自己中并且在下一个case标签之前，如果后面没有case标签，则使用[[fallthrough]]为劣构代码
2、（仅）使用default来处理一般情况（参考switch.cpp）

# 算术
1、不要混合有符号和无符号的算术运算（参考mixSignedUnsigned.cpp）
2、使用无符号类型（unsigned）进行位操作
3、使用有符号类型进行算术运算（参考signedTypes.cpp）
4、不要试图通过使用usigned来避免负值
**算术行为在signed和unsigned类型之间有所不同（参考modulo.cpp和overflow.cpp）**
**可以使用花括号来检测溢出，例如x = {x + 1000}替换x += 1000，编译器检查窄化转换，因此会检测到溢出**

## 典型的算术错误
1、避免上溢和下溢（参考overUnderflow.cpp）
**上溢和下溢为未定义行为，通常在程序运行时以崩溃告终**
2、不要除以零
