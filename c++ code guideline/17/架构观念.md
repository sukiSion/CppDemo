1、从不稳定的代码中分离稳定的代码
在稳定的和不太稳定的代码之间防止一个接口是一种分离的方式。由于接口的存在，不稳定的代码变成了一种子系统，可以单独测试或重构它。此时可以进行子系统测试和子系统集成测试。
子系统有两个进行系统的通道：
1) 功能通道：提供了子系统的功能
2) 非功能通道：传播了可能发生的异常
**由于接口的存在，具体的子系统是接口的实现，因此可以很快被另一个可能更稳定的实现所替代**
2、将潜在可复用的部分表达为程序库
**不要再代码中预先投入过多的精力以使其成为可重用的库，而是要先写出代码使其可能被复用**
需要遵循一些简单的准则：可理解、可维护和其他质量要求
**当存在两个类似的函数时，可以使用第三个函数来提供实现，原本两个类似的函数则成为这个实现函数的封装。即提供一个通用实现。**
**当直知道会重复使用某功能时，应该考虑库的问题。而只有当你会重用某功能至少两次时，才应该把他写成一个库。**
3、程序库之间不应该有循环依赖
程序库之间的循环依赖会时软件系统变得更复杂，使得库很难测试也不可能独立进行重用。
其次库会变得更难理、维护和扩展
当程序库c1和c2存在循环依赖时：
1) 重新包装c1和c2时它们不再相互依赖
2) 在物理上将c1和c2合成一个单独组件c12
3) 把c1和c2放在一起考虑，把两者单作一个单独组件c12
